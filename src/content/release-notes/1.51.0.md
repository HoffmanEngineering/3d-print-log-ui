The **Slic3r Post-Processing Uploader** (the small program that logs a print every time you export G-code from OrcaSlicer, PrusaSlicer or Bambu Studio) has a big new release, and getting it working no longer means hunting for the right settings field in your slicer. Version 1.2.0 comes with a **setup wizard**: double-click the uploader on Windows (or run it with no arguments on macOS and Linux), answer two questions, and it adds itself to every process profile OrcaSlicer, Snapmaker Orca or Anycubic Slicer Next has. It never edits the slicer's own profiles; instead you get a matching "- 3DPrintLog" user preset for each one, so you pick the logged version from the Process dropdown and slice exactly as before. Run it again after adding a printer, after moving the file, or to change the note template, and `uninstall` takes it all back out.

The uploader itself learned a lot since 1.1: it reads PrusaSlicer's binary `.bgcode` files (MK4, MINI+, XL, CORE One), sends one material entry per filament slot on multi-color prints (with the slot, color and material spelled out so you can match each to the right spool), picks the sharpest thumbnail the slicer embedded, uses the filament's real density for weight estimates, explains what went wrong in plain language when it cannot upload, and tells you when a newer version is available.

The [uploader documentation](/docs/slic3r-uploader) has been rewritten around the wizard as a five-step guide with screenshots from OrcaSlicer, plus the manual setup for PrusaSlicer and Bambu Studio, the options that control what gets logged, and a troubleshooting section.

#### Full List of Changes:

- **Setup wizard for OrcaSlicer, Snapmaker Orca and Anycubic Slicer Next** - Run the uploader with no arguments and it installs itself into every process profile as a "- 3DPrintLog" user preset. Re-running updates paths and flags; `uninstall` removes only what it created; `--dry-run` previews either. ([Uploader PR #64](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/64))
- **PrusaSlicer binary G-code** - Printers that require `.bgcode` are now supported; metadata, settings and the thumbnail are read straight from the binary container. ([Uploader PR #54](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/54))
- **PrusaSlicer 3.0** - The uploader works with the 3.0 alpha's G-code unchanged. ([Uploader PR #27](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/27))
- **Multi-color prints** - Each filament slot becomes its own material entry, labelled with the slot number, color and material, for OrcaSlicer, Bambu Studio, Anycubic Slicer Next and PrusaSlicer MMU/XL exports. ([Uploader PR #26](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/26), [Uploader PR #53](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/53))
- **Sharper print images** - The highest-resolution thumbnail up to 1280x720 embedded in the G-code is used as the print image. ([Uploader PR #22](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/22))
- **Better weight estimates** - Filament weight uses the density from the slicer profile rather than a fixed guess. ([Uploader PR #47](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/47))
- **Readable console output** - A normal run shows a short checklist of what it did; a failure explains what went wrong and what to do, and keeps the window open long enough to read it. Unknown flags are reported instead of ignored. ([Uploader PR #28](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/28), [Uploader PR #45](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/45))
- **Update notifications** - Each run checks for a newer release and prints a link when one exists. ([Uploader PR #63](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/63))
- **Faster on large files** - Only the head and tail of the G-code, where slicers write their settings, are read. ([Uploader PR #25](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/25))
- **Dry-run mode** - `--dry-run` renders the note and shows what would be uploaded without sending anything, which is the quickest way to check a custom template. ([Uploader PR #56](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/56))
- **Fixed print times over 24 hours** - Multi-day prints no longer lose their days when the time is parsed. ([Uploader PR #44](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/44))
- **Fixed a crash on G-code without filament settings** - Files that omit the filament section are handled instead of failing. ([Uploader PR #24](https://github.com/HoffmanEngineering/Slic3rPostProcessingUploader/pull/24))
- **Rewritten uploader documentation** - [Send prints from your slicer](/docs/slic3r-uploader) now walks through download, adding printers, the wizard, picking a preset and exporting, with screenshots, plus manual setup, options and troubleshooting.
